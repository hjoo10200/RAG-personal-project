# 구조화 키워드 검색 결과 분석

분석 대상은 `evaluation/keyword_structured/retrieval_results.csv`와
`evaluation/keyword_structured/retrieval_summary.json`이다. 이 평가는 Elasticsearch BM25에
긴 사용자 질문 하나를 그대로 전달하지 않고, 검색 목적별로 만든 짧은 하위 질의를 실행한 뒤
RRF(Reciprocal Rank Fusion)로 합친 결과다.

## 1. 결론

구조화 키워드 검색은 **관련 PDF를 후보로 찾는 단계에서는 성공적**이다. 15개 질문 모두에서
최소 기대 문서 수를 충족했고, 모든 질문의 첫 번째 결과가 기대 문서였다. 특히 기존 키워드
기준선에서 약했던 정책 문서 검색이 크게 개선됐다.

다만 이 결과를 검색 품질 100%로 해석하면 안 된다. 현재 평가는 주로 `올바른 PDF가 검색됐는가`를
측정한다. 실제 보고서 생성에 필요한 `올바른 페이지와 근거 문단이 검색됐는가`는 별개의 문제이며,
일부 결과에서 문서 메타데이터 점수가 청크 본문 점수를 압도하는 현상이 확인됐다.

따라서 현재 상태는 다음처럼 판정한다.

- 구조화 입력을 키워드 검색어로 변환하는 방향: 적절함
- 정책·사례·가이드 PDF 후보 검색기: 초기 목표 통과
- 생성 LLM에 바로 전달할 최종 근거 검색기: 추가 개선 필요
- 하이브리드 RAG 결합용 키워드 후보 검색기: 사용 가능

## 2. 정량 결과

| 검색 방식 | Source Hit@3 | 기대 문서 회수율 | MRR |
|---|---:|---:|---:|
| Vector-only 기준선 | 86.67% | 86.67% | 92.22% |
| 긴 자연어 BM25 기준선 | 80.00% | 80.00% | 75.56% |
| 구조화 BM25 + RRF | **100.00%** | **96.67%** | **100.00%** |

코퍼스별 구조화 검색 결과는 다음과 같다.

| 코퍼스 | 질문 수 | Source Hit@3 | 기대 문서 회수율 | MRR |
|---|---:|---:|---:|---:|
| guides | 5 | 100% | 90% | 100% |
| cases | 5 | 100% | 100% | 100% |
| policies | 5 | 100% | 100% | 100% |
| 전체 | 15 | 100% | 96.67% | 100% |

`Source Hit@3`가 100%인데 기대 문서 회수율이 96.67%인 이유는 G01 때문이다. G01은 기대 문서
2개 중 최소 1개만 찾으면 통과하도록 설정되어 있다. 실제로는 1개만 찾았으므로 Source Hit는
통과하지만 기대 문서 회수율은 50%다.

## 3. 잘 작동한 부분

### 정책명과 정책 조건 검색

P01은 서울 청년월세지원 공고와 FAQ를 각각 1위와 2위로 회수했다. P04도 희망두배 청년통장과
청년수당 문서를 함께 회수했다. 이는 `policy_name`, `document_title`, `keywords` 필드와 정책별
하위 질의가 정책 문서 선택에 효과가 있음을 보여준다.

### 긴 질문에서 분리한 검색 의도

기존 키워드 기준선에서 실패했던 이사 질의 G03이 1위에서 올바른 이사 가이드를 찾았다. 방문견적,
허가·보험, 파손 대응을 각각 별도 하위 질의로 검색한 개선 효과다.

### 서로 다른 유형의 사례 문서 회수

C03은 생활비 통계 문서와 소득 공백·생활 위험 면담 문서를 모두 회수했다. 수치 근거와 사례 근거를
함께 사용하는 보고서 생성 목적에 알맞은 결과다.

## 4. 확인된 문제

### 4.1 G01의 두 번째 기대 문서 누락

G01은 표준계약서와 주택임대차보호 가이드를 함께 기대했지만, Top 3가 모두
`standard_housing_lease_contract_2023.pdf`였다. 별도로 두 번째 하위 질의를 Top 10까지 조회해도
전부 표준계약서 청크였다.

현재 `max_per_source=1`은 후보 집합에 다른 출처가 존재할 때만 출처 다양성을 보장한다. 후보 단계가
한 문서로만 채워지면 최종 부족분을 같은 문서로 다시 채우므로 이 문제를 해결하지 못한다.

### 4.2 동일 문서의 모든 청크가 비슷한 점수를 받는 현상

G01 Top 10의 BM25 점수는 모두 `10.8508`이었다. 각 청크에 동일하게 복제된 제목·정책명·검색
키워드가 강한 가중치를 받기 때문에, 올바른 문서는 잘 고르지만 그 문서 안에서 가장 적합한 본문을
구분하기 어려워진다.

이 현상은 다른 결과에서도 보인다.

- G03 2위는 이사 가이드의 면책·안내 문단으로, 직접적인 답변 근거가 약하다.
- P03 Top 3는 모두 LH 문서 1페이지 청크다. 문서는 맞지만 자격, 순위, 제출서류 등 서로 다른
  핵심 구간을 충분히 회수하지 못했다.
- P05 1위는 사업 추진체계, 3위는 참여대학 관련 문단이다. 질문의 핵심인 신청자격, 원거리 기준,
  지원 가능 주거비보다 우선순위가 높다고 보기 어렵다.

즉 현재의 MRR 1.0은 `기대 PDF가 1위`라는 뜻이지 `가장 좋은 근거 문단이 1위`라는 뜻은 아니다.

### 4.3 평가 데이터가 실제 사용자 입력보다 쉬움

현재 평가 파일에는 사람이 만든 `keyword_queries`가 들어 있으며, 정책 질의에는 정확한 정책명과
연도가 포함된다. 인덱스의 검색 메타데이터에도 동일한 정책명과 관련 키워드가 있다. 따라서 이번
평가는 다음 연결이 정상인지 확인하는 구성요소 시험에 가깝다.

```text
정제된 하위 질의 -> Elasticsearch 필드 검색 -> RRF -> 기대 PDF
```

반면 실제 서비스에서는 사용자가 입력한 연령, 지역, 취업·학업 상태, 주거 형태 등을 검색기가
정확한 하위 질의로 변환해야 한다. 현재 결과만으로는 이 변환 단계의 일반화 성능을 입증할 수 없다.

### 4.4 Source Hit 중심 평가지표의 한계

현재 자동 점수는 출처 파일 기준이다. 다음 항목은 자동 채점하지 않는다.

- 검색 청크가 질문의 핵심 개념을 실제로 포함하는지
- 정책 자격과 지원 내용이 서로 다른 페이지에 흩어졌을 때 충분히 회수했는지
- 같은 내용을 반복하는 청크가 Top K를 차지하는지
- 관련 없는 정책이 함께 검색되는 거짓 양성(false positive)이 있는지
- 최신성 및 적용 시점이 사용자 상황과 맞는지

## 5. 원인 해석

현재 검색식은 `policy_name`, `document_title`, `keywords`에 높은 가중치를 주고 모든 청크를 한 번에
검색한다. 이 방식은 문서 식별과 문서 내부 문단 검색이라는 서로 다른 문제를 한 점수로 해결하려 한다.

```text
정확한 정책명·문서명
        ↓ 강한 가중치
올바른 PDF의 모든 청크가 상위 후보가 됨
        ↓
문서 선택은 좋아지지만 문서 내부의 근거 문단 순위가 흐려짐
```

RRF도 각 하위 질의에서 이미 검색된 후보만 합칠 수 있다. 특정 하위 질의의 상위 후보가 한 문서에
쏠리면 RRF 이후에 다른 문서를 복원할 수 없다.

## 6. 다음 개선 순서

### 1단계: 하위 질의별 최소 후보 보존

각 하위 질의의 1위 또는 출처별 1개를 먼저 확보한 뒤 나머지를 RRF 순위로 채운다. G01처럼 서로
다른 역할의 하위 질의가 한 문서에 흡수되는 현상을 줄일 수 있다. 후보 수는 현재 5개보다 늘려
10개에서 비교하되, 최종 Top K는 그대로 유지해도 된다.

### 2단계: 문서 선택과 문서 내부 검색 분리

정책명·문서명·메타데이터로 PDF 후보를 고른 다음, 선택된 PDF 안에서는 `content` 중심으로 다시
검색하는 2단계 방식을 권장한다.

```text
1차: 정책명·지역·대상 조건으로 문서 후보 선택
2차: 자격·지원금·신청방법·주의사항별 본문 청크 검색
```

최소 변경안은 최종 재정렬 시 메타데이터 점수보다 본문 일치도를 더 크게 반영하는 것이다.

### 3단계: 실제 구조화 입력의 종단 간 평가

새 평가 세트에는 사람이 만든 `keyword_queries`를 넣지 않고 실제 `UserSituation` 필드만 둔다.
평가 실행 중 `build_structured_keyword_queries()`가 직접 하위 질의를 만들게 해야 한다.

포함할 시험 사례는 다음과 같다.

- 같은 상황을 표현만 바꾼 패러프레이즈
- 일부 필드가 비어 있거나 `unknown`인 상황
- 서울 외 지역과 정책 적용 지역이 불일치하는 상황
- 취업자, 취업준비생, 대학생 등 상태별 정책 후보 변화
- 월세·전세·기숙사 등 주거 형태별 검색 변화
- 지원 대상이 아닌 상황에서 관련 없는 정책을 과도하게 추천하지 않는지 확인하는 음성 사례

### 4단계: 근거 품질 평가 추가

기존 Source Hit 지표는 유지하되, 청크별로 다음 지표를 추가한다.

- Evidence Pass@3: 답변 가능한 근거가 하나 이상 존재
- Strong Evidence@3: 핵심 조건과 수치까지 포함
- Query Coverage: 하위 질의별 최소 한 개의 근거 회수
- Source/Page Diversity: 동일 출처·동일 페이지 반복 비율
- False Positive Rate: 상황에 맞지 않는 정책 비율

이 검증이 끝난 뒤 Vector 검색 결과와 결합해 Hybrid RAG를 평가하는 것이 안전하다.

## 7. 최종 판정

구조화 키워드 검색은 긴 문장형 BM25보다 확실히 개선됐고, 특히 명칭과 조건이 중요한 정책 문서의
후보 검색기로서 가치가 있다. 그러나 현재 100%라는 수치는 **정제된 질의로 기대 PDF를 찾은 성능**을
뜻한다. 실제 사용자 입력에서 올바른 정책과 최적의 근거 문단을 찾는 전체 성능으로 주장해서는 안 된다.

따라서 다음 구현 목표는 검색 방식을 다시 바꾸는 것이 아니라, `하위 질의 생성 -> 문서 후보 선택 ->
문서 내부 근거 검색`을 분리하고 실제 구조화 입력 기반의 블라인드 평가를 추가하는 것이다.

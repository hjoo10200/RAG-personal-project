# Elasticsearch BM25 키워드 검색 평가 보고서

평가일: 2026-08-18  
평가 질문: 15개  
검색 방식: Elasticsearch BM25, Top 3  
비교 기준: `evaluation/baselines/vector_only_2026-08-17/`

> 후속 개선 상태: 이 보고서는 긴 자연어 질문 전체와 기존 `standard` 필드를 사용한 최초 평가 결과를 기록한다. 이후 구조화 입력 스키마, Keyword 전용 하위 질의, 한국어 문서 제목·정책명·별칭 메타데이터, n-gram 보조 필드, 하위 질의 RRF와 출처 다양화를 코드에 반영했다. 사용자의 요청에 따라 새 매핑의 Elasticsearch 적재와 개선 후 평가는 아직 실행하지 않았다. 새 결과는 `evaluation/keyword_structured/`에 별도로 생성한다.

## 결론

현재 Keyword-only 검색은 Source Hit@3 80.0%, MRR 0.7556으로 Vector-only 기준선보다 낮다. 현재 상태의 BM25 결과를 그대로 실제 RAG에 사용하거나 곧바로 RRF에 결합하는 것은 권장하지 않는다.

다만 Keyword 검색이 완전히 불필요한 것은 아니다. G05에서는 Vector가 한 PDF에 편중되어 놓친 두 번째 기대 문서를 회수했고, C02에서는 Vector 2위였던 기대 사례 문서를 1위로 올렸다. 따라서 한국어 분석기, Keyword 질의 구성과 출처 다양성을 개선한 후 Vector 검색의 보완 후보 생성기로 사용하는 방향이 적절하다.

## Keyword 검색이 보완한 부분

### G05: 계약 갱신 관련 두 문서 회수

질문은 묵시적 갱신과 계약갱신요구권의 차이 및 통지 시점을 물었다. 기대 문서는 주택임대차보호법 해설집과 표준 임대차계약서 두 개다.

```text
Vector Top 3
1. housing_lease_protection_guide_2020.pdf
2. housing_lease_protection_guide_2020.pdf
3. housing_lease_protection_guide_2020.pdf

Keyword Top 3
1. housing_lease_protection_guide_2020.pdf
2. housing_lease_protection_guide_2020.pdf
3. standard_housing_lease_contract_2023.pdf
```

Vector 기대 문서 회수율은 50%였지만 Keyword는 100%였다. `묵시적 갱신`, `계약갱신요구권`처럼 법률 문서에 실제 등장하는 용어가 Keyword 검색에 유리하게 작용했다. 이는 Hybrid 검색에서 BM25를 유지할 가장 분명한 근거다.

### C02: 자립 지연 당사자 사례를 1위로 상승

부모와 동거하며 독립을 미룬 이유를 묻는 질문에서 기대 문서는 `transition_to_adulthood_independence_interviews_2022.pdf`다.

```text
Vector 기대 문서 순위: 2위
Keyword 기대 문서 순위: 1위
```

Keyword 1위 청크에는 `성인으로의 전환을 망설이는 이유`, `자립 조건의 미충족`, `자립 격차`가 직접 포함되어 있었다. 질문의 핵심 용어와 원문의 표현이 비교적 잘 일치한 사례다.

## 실패 분석

### G03: 한국어가 붙어서 추출된 PDF를 standard analyzer가 처리하지 못함

질문은 방문견적, 이사업체 허가, 피해배상보험과 파손 대응을 물었다. 기대 문서인 `easylaw_moving_guide_2026.pdf`에는 실제로 모든 개념이 포함되어 있다.

```text
이사업체의방문견적을받아산출하는것이가장좋습니다
허가받은이사업체인지꼭확인하세요
500만원이상의피해배상이행보증보험에가입하고있어
이삿짐의파손
```

하지만 PDF 추출 결과의 한국어 단어 사이가 붙어 있다. 현재 Elasticsearch의 `standard` tokenizer는 이를 `방문견적`, `허가`, `피해배상`, `파손`과 같은 유효한 검색 단위로 충분히 분해하지 못했다.

Top 10에도 기대 PDF는 없었으며 금융 가이드와 임대차 해설집의 일반적인 `비교`, `계약`, `확인`, `방법` 표현이 대신 검색됐다. 이는 문서 내용 부재가 아니라 한국어 분석과 추출 텍스트 형태의 문제다.

### P01: 관련성은 높지만 FAQ 한 파일이 결과를 독점

질문은 청년월세지원의 임차 조건, 건강보험 피부양자 소득과 제출서류를 함께 물었다. Keyword Top 3는 모두 FAQ였고 기대 공고문은 회수되지 않았다.

```text
1. FAQ p.5  : 보증금·월세·공동임차인
2. FAQ p.30 : 건강보험 피부양자 소득
3. FAQ p.28 : 제출서류
```

세 청크 모두 질문과 실제로 관련 있으므로 검색 관련성 자체는 높다. 실패 원인은 평가가 공고문과 FAQ 두 출처를 모두 요구하지만 한 PDF가 Top 3를 독점한 데 있다. Vector 검색도 같은 질문에서 FAQ만 가져와 실패했다.

이 질문은 검색 후보를 `자격·기본조건`과 `피부양자·서류 예외`로 나누거나, 최종 선택에서 원본 PDF별 최대 결과 수를 제한해야 한다.

### P04: 사용자 표현과 공식 정책명 불일치

질문에는 `청년수당`은 정확히 들어 있지만 `희망두배 청년통장` 대신 `근로 청년 저축지원`이라는 설명형 표현이 사용됐다.

Keyword Top 3는 모두 청년월세지원 FAQ였으며 청년수당 공고는 4위, 희망두배 청년통장 공고는 Top 10에도 없었다.

```text
1~3위: 청년월세지원 FAQ
4위: 서울 청년수당 공고
희망두배 청년통장 공고: Top 10 밖
```

BM25는 `근로 청년 저축지원`과 공식 사업명 `희망두배 청년통장`의 의미적 동등성을 알지 못한다. 또한 `서울`, `청년`, `지원`, `신청`, `중복` 같은 일반 단어가 많이 등장하는 월세 FAQ가 높은 점수를 받았다.

이 문제는 정책 별칭 사전, 구조화된 정책명 필드 또는 Vector 검색과의 결합이 필요하다. 복합 비교 질문을 두 정책별 하위 질의로 분해하지 않으면 Top 3에서 두 문서를 동시에 회수하기 어렵다.

## 통과했지만 주의가 필요한 결과

### C03

기대 생활비 문서는 Keyword 3위에만 등장했고 1위는 질문과 직접 관련이 낮은 정책 접근 사례였다. Source Hit 판정은 통과했지만 실제 근거 품질은 Vector 검색보다 낮다.

### C05

기대 정책 접근 인터뷰는 Keyword 2위였다. 1위의 청년 생활위험 인터뷰는 정책 지원 일반론을 포함하지만 `어디서 정책 정보를 알았고 신청 과정에서 무엇이 어려웠는가`라는 질문에는 기대 문서보다 덜 직접적이다.

### P03

질문에 `LH 청년 매입임대`가 직접 들어 있는데도 청년월세지원 FAQ가 1위, 기대 LH 공고가 2위였다. 현재 `match_phrase`는 긴 자연어 질문 전체를 사용하므로 실제 문서에서 문장 전체가 일치할 가능성이 낮다. 결국 `multi_match`의 일반 단어 OR 검색이 순위를 크게 좌우한다.

## 구조적 원인

### 1. 자연어 질문 전체를 Keyword 질의로 사용

현재 `build_keyword_query()`는 사용자의 긴 질문 전체를 `match_phrase`와 `multi_match`에 전달한다. 긴 질문 전체가 문서에 그대로 등장하지 않으므로 `match_phrase`는 대부분 기여하지 못하고, `multi_match`의 일반 단어 OR 검색이 사실상 결과를 결정한다.

Keyword 검색에는 전체 자연어 질문보다 정책명, 지역명, 법률 용어와 핵심 명사구를 추출한 별도 질의가 필요하다.

### 2. 한국어 형태소 분석기 부재

현재 매핑은 플러그인이 필요 없는 `standard` tokenizer를 사용한다. 공백이 정상인 일반 문장에는 동작하지만 G03처럼 PDF 추출 과정에서 한국어가 붙은 경우 핵심 단어를 분해하지 못한다.

### 3. 한국어 문서 제목 필드 부재

`source_file`은 `seoul_hope_double_youth_account_notice_2026.pdf`처럼 영문 파일명이다. 사용자의 한국어 정책명과 일치하지 않으므로 파일명 가중치 2.0의 효과가 제한적이다.

### 4. 동일 원본 PDF 결과 제한 없음

Elasticsearch는 관련 청크를 점수 순으로 그대로 반환한다. FAQ처럼 질문의 여러 표현이 반복되는 문서는 Top-K 전체를 독점할 수 있다.

### 5. 복합 질문 분해 없음

한 질문에서 두 정책이나 여러 하위 주제를 요구해도 단일 BM25 검색만 실행한다. P01과 P04처럼 복수 출처를 요구하는 질문에서 특히 불리하다.

## RRF 전 수정 우선순위

현재 결과를 그대로 RRF에 결합하지 말고 다음 순서로 Keyword 검색을 먼저 개선한다.

1. 한국어 분석기를 개선한다. 우선 `analysis-nori`를 적용하고, 붙어서 추출된 문자열 대응이 부족하면 n-gram 보조 필드를 검토한다.
2. 자연어 질문 전체와 별도로 고유명사·정책명·계약 용어 중심의 Keyword 질의를 생성한다.
3. PDF별 한국어 `document_title`과 정책 문서의 `policy_name`, 별칭을 메타데이터에 추가해 가중 검색한다.
4. 한 원본 PDF가 최종 Top-K를 독점하지 않도록 source별 결과 수를 제한한다.
5. 두 정책 비교나 자격·예외를 함께 묻는 질문을 하위 질의로 분해한다.
6. 같은 15개 질문으로 Keyword 평가를 다시 실행한다.
7. 개선된 Keyword 결과가 확인된 뒤 Vector와 RRF를 결합한다.

## Hybrid 적용 판단 기준

Keyword-only가 반드시 Vector-only 전체 점수를 넘어야 하는 것은 아니다. Hybrid의 목적은 두 방식이 서로 놓치는 문서를 보완하는 것이다. 다만 최소한 다음 조건을 확인한 후 결합해야 한다.

- G03처럼 핵심 단어가 원문에 있는데 Top 10에도 없는 분석 실패를 해결할 것
- 정책명이 명시된 P03에서 기대 정책 공고가 Keyword Top 1에 가까워질 것
- P01과 P04의 복합 질문에서 서로 다른 기대 문서를 후보군에 포함할 것
- 일반 단어 때문에 무관한 월세 FAQ가 반복적으로 상위에 오르는 현상을 줄일 것
- 개선 후 Source Hit@3이 현재 80%보다 떨어지지 않을 것

그 후 Vector Top-N과 Keyword Top-N을 각각 가져와 점수 자체가 아닌 순위를 RRF로 결합하고, `chunk_id` 중복 제거와 source 다양화를 적용해야 한다.

## 평가 중 발견한 실행 문제

Top 10 결과를 확인하는 과정에서 PDF 본문의 특수 불릿 문자가 Windows CP949 콘솔에 출력되지 않아 `UnicodeEncodeError`가 발생했다. 검색은 정상 완료됐고 출력 단계만 실패한 문제였다.

`src/retrieval/keyword_search.py`에서 표준 출력의 인코딩 오류를 대체 문자로 처리하도록 수정했으며, 이후 동일한 Top 10 검색이 정상 종료되는 것을 확인했다.
